# Поток 2.0 — выписки, месяцы и архив

Статический сайт для GitHub Pages с настоящей регистрацией через Supabase. Логин — email. В комплекте нет ключей или подключённой базы: сначала выполните настройку ниже. Без неё доступен только демонстрационный режим с вымышленными данными.

## Быстрый запуск

1. **Сохраните резервную копию старой версии** кнопкой «Резервная копия». Не очищайте данные браузера.
2. Создайте проект на https://supabase.com/dashboard. В **SQL Editor → New query** вставьте весь файл `supabase/schema.sql` и нажмите **Run**. Создаются таблицы, правила доступа и закрытое хранилище файлов. Скрипт можно запускать повторно: данные не удаляются.
3. В настройках проекта найдите **Project URL** и **Publishable key** (`sb_publishable_...`). Впишите их в `config.js`. Удобный генератор этого файла есть в `setup.html` — его можно открыть локально. Secret key, service_role, пароль базы и SMTP-пароль не должны попадать в GitHub.
4. В **Authentication → URL Configuration** задайте Site URL `https://glebchik230.github.io/POTOK/`. Добавьте в Redirect URLs этот же адрес и `https://glebchik230.github.io/POTOK/index.html`. Для другого домена используйте фактический адрес сайта.
5. В **Authentication** включите вход и регистрацию по email/password, оставьте подтверждение email включённым, установите минимальную длину пароля не менее 8 символов. Настройте **Custom SMTP** для писем подтверждения и восстановления. Встроенная тестовая почта Supabase отправляет письма только адресам участников команды проекта; для обычных пользователей нужен собственный SMTP. Документация: https://supabase.com/docs/guides/auth/auth-smtp
6. Замените файлы в корне репозитория POTOK содержимым архива. `index.html` должен лежать в корне, рядом с `app.js`, `features.js`, `cloud.js`, `config.js`, `core.js`, `parser.js`, `style.css`; сохраните папки `vendor`, `assets`, `supabase`. Не загружайте сам ZIP вместо его содержимого. `.nojekyll` можно добавить через GitHub отдельно, если он скрыт в проводнике.
7. **GitHub → Settings → Pages → Deploy from a branch → main → / (root) → Save**. Сборка Node.js для сайта не нужна. Дождитесь успешного Pages deployment, затем откройте сайт и обновите страницу с очисткой кеша.
8. Зарегистрируйтесь, подтвердите email, войдите. Проверьте загрузку тестовой выписки, скачивание её оригинала и выход/повторный вход. Создайте второй тестовый аккаунт: в нём не должно быть данных первого.

Настройка с теми же шагами и генератором config.js: `setup.html`.

## Что добавлено

- Вход, регистрация, подтверждение email и восстановление пароля. Данные каждого аккаунта отделены правилами доступа базы и хранилища.
- «Месяцы»: входящий остаток, приход, расход, конечный остаток по всем счетам и отдельно по каждому. Закрытие фиксирует отчёт и операции на сервере.
- Закрытие блокирует изменение всей истории до конца месяца. Для исправлений сначала откройте самый поздний закрытый месяц, затем более ранние. Требуется причина; прежние отчёты остаются в истории.
- «Архив»: оригинальные загруженные файлы, поиск по имени/банку/счёту, фильтр периода, скачивание и переход к операциям.
- «Операции»: суммы от большей к меньшей и наоборот. Сравнивается размер операции **по модулю**; для самых больших расходов выберите «Расходы» и «Сначала крупные».
- «Как пользоваться»: шесть шагов, пять схем интерфейса, пояснения к файлам, остаткам, закрытию и архиву.

## Порядок работы

Выгрузите из банка выписку за полный календарный месяц. Предпочтительны XLSX/XLS или 1C TXT, также поддерживаются CSV и текстовые PDF. Фото и сканы PDF без текстового слоя не распознаются. После загрузки проверьте счёт, даты, колонки списания/зачисления, начальный и конечный остатки. Пропущенные строки видны в предпросмотре. Только после проверки подтвердите импорт.

Выберите месяц, проверьте полноту выписок по всем счетам и остатки. Текущий/будущий месяц, месяц без операций, без известного входящего остатка или с отмеченными ошибками импорта закрыть нельзя. Пробелы в покрытии периодов показываются предупреждением: пользователь подтверждает полноту вручную. Программа не знает об отсутствующих банковских счетах и не может гарантировать полноту без сверки с банком.

Все суммы ведутся в рублях (внутри — целые копейки). Не объединяйте валютные счета: конвертации валют нет. Собственные переводы учитываются в движениях; для анализа затрат исключайте их фильтром. Категории определяются правилами по назначению платежа и редактируются вручную. ИИ в этой версии не подключён.

## Перенос старых данных

После входа в пустой аккаунт на том же домене и в том же браузере появится кнопка переноса локальной версии. Нажмите её и подтвердите адрес аккаунта. Старая копия не удаляется. Если домен или браузер другой, восстановите ранее выгруженный JSON через «Восстановить».

Старая версия не сохраняла сами исходные файлы. Загрузите их повторно: совпадающий SHA-256 прикрепит оригинал к прежней выписке без повторного импорта операций. Изменённый файл нужно проверять как новую выписку. Если файл сохранился в архив, но операции не сохранились (например, период закрыт), он останется доступен для скачивания; после исправления причины загрузите его ещё раз.

Резервный JSON содержит операции, сведения о выписках, историю закрытий и индекс архива, **но не сами оригиналы**. Скачивайте оригиналы из архива отдельно. Восстановление JSON заменяет текущие операции, не перезаписывает серверную историю закрытий и не обходит блокировку. Копии со ссылками на файлы другого аккаунта не принимаются. Архивные оригиналы неизменяемы; удаление импорта удаляет операции, но оставляет оригинал в архиве.

## Ограничения и проверка

- Нужен интернет. Изменение считается сохранённым только после успешного ответа сервера; при ошибке остаются прежние данные.
- Один файл до 30 МБ, один аккаунт до 20 000 операций / 16 МБ данных учёта. Объём файлов зависит от тарифа Supabase.
- При одновременном изменении в разных вкладках появится конфликт. Нажмите «Обновить» и повторите действие.
- Граница текущего месяца и время истории — UTC+5 (Екатеринбург).
- Supabase хранит пароли и управляет сессиями. В браузере сохраняется токен входа; на общем компьютере нажимайте «Выйти».
- Подключение к реальному Supabase, доставка писем и фактический GitHub deployment должны быть проверены после внесения конфигурации. У автора сборки нет вашего проекта/ключей.

## Для разработчика

Статический клиент без сборки. `vendor/supabase.min.js` — bundled @supabase/supabase-js 2.118.0, лицензия рядом. Парсеры исходной версии сохранены. `core.js` — расчёт месяцев и сортировка; `features.js` — интерфейс v2; `cloud.js` — API; `supabase/schema.sql` — RLS и серверные функции. Не делайте bucket публичным и не разрешайте прямые UPDATE таблиц: изменение выполняется через проверяющие RPC.

Node.js 24+: `npm install`, затем `npm test`. Проверяются парсер, арифметика месяцев, DOM-сценарии и SQL в PGlite со служебными схемами auth/storage: изоляция аккаунтов, запрет анонимного доступа, архивные оригиналы, конфликты версий, закрытие/открытие месяцев и сохранность снимков. Это не заменяет проверку SMTP и Storage API на реальном Supabase.
