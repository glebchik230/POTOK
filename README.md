# Поток — приложение для банковских выписок

Готовое браузерное приложение на HTML, CSS и JavaScript. Сборка и установка npm-пакетов для запуска не нужны. Библиотеки чтения Excel и PDF включены в папку `vendor`.

## Что работает

- Загрузка XLSX, XLS, CSV, TXT в формате 1С / Клиент-банк.
- Извлечение таблиц из PDF с текстовым слоем; может потребоваться настройка колонок.
- Проверка распознанных операций перед импортом.
- Приход, списания, денежный поток и расчётный остаток.
- Сверка с итогами и остатками выписки, если они обнаружены.
- Автоматические категории по правилам и ручная корректировка категории операции.
- Поиск, фильтры по месяцу и счёту, просмотр назначения платежа.
- Защита от повторной загрузки файла и совпадающих операций.
- Экспорт CSV, сохранение и восстановление резервной копии JSON.

ИИ пока не подключён: автоматические категории определяются правилами в `parser.js`. Фотографии и PDF-сканы не распознаются. Учёт рассчитан на рублёвые счета.

## Загрузить на GitHub

1. Распакуйте архив. Откройте папку `potok`.
2. Создайте репозиторий на GitHub, например `potok`.
3. На странице репозитория выберите загрузку файлов: `Add file → Upload files` (в пустом репозитории — `uploading an existing file`).
4. Перетащите **содержимое** папки `potok`, включая `vendor` и `tests`. Файл `index.html` должен оказаться в корне репозитория, а не внутри дополнительной папки. Не загружайте сам ZIP вместо исходников.
5. Сохраните изменения кнопкой `Commit changes`.

Можно хранить код в закрытом репозитории. Доступность GitHub Pages для закрытого репозитория зависит от тарифа. Для GitHub Free используйте публичный репозиторий, если хотите публиковать через Pages.

## Открыть приложение через GitHub Pages

1. В репозитории откройте `Settings → Pages`.
2. В блоке `Build and deployment` укажите `Source: Deploy from a branch`.
3. Выберите ветку `main`, папку `/(root)` и нажмите `Save`.
4. Дождитесь завершения публикации. Адрес появится в разделе Pages; обычно он выглядит как `https://ВАШ-ЛОГИН.github.io/potok/`.
5. Откройте адрес и нажмите «Загрузить выписку».

У GitHub Pages будет собственный публичный адрес приложения; доступ «только для вас» из первоначального размещения туда не переносится. Приватность загруженных операций обеспечивается тем, что приложение обрабатывает и хранит их локально в браузере, а не в репозитории. Не добавляйте реальные выписки или резервные копии в GitHub.

Актуальная документация GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Запустить на компьютере

Установите Python 3, откройте терминал в папке с `index.html` и выполните:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

В Windows вместо `python3` можно использовать `py`:

```powershell
py -m http.server 8000 --bind 127.0.0.1
```

Откройте http://localhost:8000. Для остановки нажмите Ctrl+C в терминале.

Запускайте через локальный сервер или HTTPS, а не двойным щелчком по `index.html`: PDF-модули и API браузера могут не работать при `file://`.

## Перенос существующих данных

1. В ранее опубликованном приложении нажмите «Скачать резервную копию».
2. Откройте новую версию приложения по адресу GitHub Pages или localhost.
3. Нажмите «Восстановить из копии» и выберите JSON-файл.

Разные адреса и разные браузеры используют отдельные хранилища. Автоматической синхронизации нет. Очистка данных сайта удаляет локальную историю; периодически сохраняйте резервные копии. Восстановление копии заменяет текущие данные.

## Файлы для редактирования

| Файл | Назначение |
| --- | --- |
| `index.html` | Структура страниц и текст интерфейса |
| `style.css` | Внешний вид и мобильная адаптация |
| `app.js` | Импорт, фильтры, графики, хранение, экспорт |
| `parser.js` | Распознавание колонок, дат, сумм, правила категорий |
| `vendor/` | Локальные библиотеки SheetJS и PDF.js |
| `tests/parser.test.cjs` | Проверки парсера на искусственных примерах |

Для запуска проверок нужен Node.js:

```bash
node tests/parser.test.cjs
```

Парсер ранее проверен на двух форматах выписок — СберБизнес и Точка: рассчитанные обороты и конечные остатки совпали с банковскими итогами. Сами выписки в исходники не включены. Другие форматы требуют проверки и при необходимости ручного выбора колонок. Полная визуальная проверка интерфейса в браузере не завершена.

## Особенности расчётов

- Деньги хранятся в целых копейках.
- Приход включает все зачисления, списания включают все исходящие движения.
- Денежный поток — приход минус списания, он не равен прибыли.
- Собственные переводы выделяются отдельной категорией, но остаются в движениях счёта.
- Остаток рассчитывается от известного входящего остатка по загруженным движениям. Пропущенные периоды могут сделать расчёт неполным.
- Категории — предположения по тексту платежа, их необходимо проверять.

## Будущее подключение ИИ

Потребуется серверная часть с API анализа и чатом. Секретный API-ключ должен храниться на сервере. Нельзя добавлять его в `app.js`, HTML или публичный репозиторий. GitHub Pages размещает статические файлы; для серверной части понадобится отдельное размещение.
